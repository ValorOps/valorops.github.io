**01 review (web-review pass, desktop/768/390/360 rendered), second-pass candidates, not yet fixed:**
1. Must fix before reuse on valor-ops.com: the frost hides the deliverables, which are purchase-deciding information, and on phones nothing signals the pane is tappable. Glass should conceal secondary detail (evidence, methodology), never what the visitor is deciding on. Add an in-glass hint on touch or move the frost to the sample finding.
2. Should fix: "Inspect" does not say what happens ("Show what you receive"), and the pill buttons break the card radius scale (14px cards, 999px buttons). Use one radius family.
3. Should fix: large prices in Geist Mono read as "$1 , 500" because of the monospaced comma. Set big amounts in Archivo with tabular-nums; keep mono for durations and labels.

**Dillan's verdict on 01 (2026-11-19, live review):** the flat black ground is fine, but the textured cards still read flat. Glass is rejected for this use: a potential client will not uncover what is being offered. Rule for the skill: never put purchase-deciding information behind glass or any interaction.

**Dillan's verdict on 01b (2026-11-19, phone):** prefers this look clearly over 01; likes selecting package and team size. Glows work. Not sold on the signal-orange scheme. The wires going dark about a second after a change read as broken.
**01b.1 changes:** wires now stay lit in the accent colour and flow continuously (1.6s loop), speed up for 450ms on change, pause off screen via IntersectionObserver, and stay static but lit under reduced motion. Added a palette switcher (Arctic default, Signal, Phosphor, Oxide) via `html[data-palette]` token sets, loaded from a non-deferred `palette.js` in the head so there is no flash; choice persists in `?palette=` and localStorage. Lesson: a status wire that animates only on change reads as a glitch; animate the steady state and use the change as emphasis.

**01b.2 fix (2026-11-20):** Dillan reported the palette picker not changing colours. Root cause: buttons and selected options transition `background-color`, and the colour comes from a custom property changed on `html`. Hidden tabs freeze transitions at their start value and WebKit can skip transitions driven by a changed custom property, so those elements kept the old palette while the rest updated. Fix: add `html.palette-switching` (transition: none on everything) for the switch, force a style flush, remove it two frames later. Skill rule: any theme or palette switch turns transitions off for the swap.
